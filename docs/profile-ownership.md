# Profile and configuration ownership

`profiles/arch-linux.md` and `profiles/macos.md` describe **candidate** destinations and exclusions, not selected machine targets. No default OS or machine is implied by the current Arch host. Before activation, the owner must confirm the first target machine, OS/version, device restrictions, and desired tools. Inspect the selected machine's existing files and effective application settings; neither this repository nor a file's presence proves that it is active. No live configuration was changed to establish these profiles.

## Source, target and override rules

- `config/<tool>/` is the authoritative repository source for imported shared tool files. Profiles name which files can be considered on each OS; they are not overlays and do not replace shared files. The old `nvim-config` import is historical, not a second maintained source. Local configuration and credentials remain outside Git.
- The selected host's *existing* files remain authoritative for live behavior until an explicitly approved deployment replaces individual destinations. No automatic profile selection, merge of repository and live files, or installation of packages exists. A machine-specific exception must be recorded for that target before use; it does not silently override a shared source file or become a tracked copy of credentials.
- `scripts/deploy-config.sh` links selected shared files from the **current checkout** (including uncommitted content) into explicit user destinations. Precedence for a managed destination is: approved repository link at that path, otherwise its existing local file. A backed-up local file is no longer loaded at that path. This is path ownership, **not** application-wide override precedence: other app search paths, includes, environment variables, and later-loaded files can still win. Inspect effective settings after apply.
- Neovim: candidate destination `$HOME/.config/nvim/init.lua` and `lazy-lock.json`; main `init.lua` with lazy.nvim is the initial **proposed** baseline. The mobile `vim.pack` alternative is deferred, never selected by this script, and has no shared lockfile. Do not mix plugin managers or treat an installed Neovim binary as evidence that this config loaded.
- Ghostty: choose an active path after checking all candidates. On Arch inspect `$HOME/.config/ghostty/config` and `config.ghostty`; on macOS also inspect `~/Library/Application Support/com.mitchellh.ghostty/config` and `config.ghostty`. macOS-specific files load after XDG files and may override them. Linking an XDG file while another file wins does not activate this source. The script requires `--ghostty-dest` rather than guessing.
- Kitty (Arch only): its `kitty.conf` includes relative theme files; deploy those together. `kitty.conf.bak` stays archival. tmux uses `$HOME/.tmux.conf`, but TPM plugins are independent user state. Bash is excluded. Pi/Limen/Herdr configuration and credentials are not owned by these profiles.

The script previews by default and backs up conflicting user files on approved apply. It does not manage app-specific override files, install packages or validate loaded behavior. Review exact preview paths and conflicts, obtain explicit approval, then verify the actual application and retain backups. To recover, remove only links still pointing into this checkout, and restore only the matching named backup after checking for later edits. See [the deployment guide](deploy-config.md) for preflight, partial-run and rollback details.
