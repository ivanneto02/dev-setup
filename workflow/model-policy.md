# ChatGPT OAuth model policy

**Only route:** Pi's `openai` provider with a ChatGPT-plan OAuth credential. An OAuth request may use a provider API endpoint; that does not make it an API-key-billed request. OpenAI API keys are **never** allowed, even as a fallback. No paid extra usage or separately billed budget is approved. Local inference is a different route and is not approved by this policy. Do not switch to `openai-codex`, a proxy, another provider, or a different model without a new owner decision. If the approved route fails, stop; do not try a second credential.

| Role | Explicit Pi route | Thinking | Escalation |

| Interactive coordinator | `openai/gpt-6-sol` | medium | Use high only for a specific reasoning failure after checking plan availability; otherwise stop and ask. |
| Bounded implementation worker | `openai/gpt-6-sol` | medium | Use high on a new bounded attempt only after a specific failure and route recheck. |
| Independent reviewer | `openai/gpt-6-sol` | high | Report unresolved findings; do not automatically escalate the model or route. |

The owner selected ChatGPT OAuth only, with no OpenAI API-key support now or later and no paid extra usage. This model was proven to accept a bounded trial; it is not proven cheapest or best for every task. Do not save these choices as global Pi defaults. The owner's route decision applies to authorized tasks and subagents without per-job permission. Check route/auth before each new job, but do not require an unobservable account-level entitlement check for every launch. Authentication metadata does not prove billing or that paid extra usage is disabled; if a response or account notice indicates billing or entitlement changed, stop and ask. The owner can review/disable paid extra usage in the account outside this repository; no hard billing guard is supplied. Select the route explicitly for the interactive coordinator (`pi --provider openai --model gpt-6-sol --thinking medium`) and for each Limen job (`--engine pi --provider openai --model gpt-6-sol --thinking medium`, or `high` for review). Do not rely on Limen's default `openai-codex/gpt-6-astra:high`, the saved Pi default, or a parent job's route. Check the actual launch arguments and auth again on continuations.

## Preflight and stop rules

Run `pi auth check --provider openai --model gpt-6-sol --json --no-refresh` and inspect **only** `status`, `provider`, and `authType`: require `ready`, `openai`, and `oauth`. Never use `--credentials`, `print-api-key`, or `print-bearer-token`; never log credentials or copy Pi's user-level `auth.json` into Git. If the check fails, expires, or reports a different type, stop; a separate interactive sign-in decision is needed. Check that no `--api-key` was passed, `OPENAI_API_KEY` is unset in the launching environment, and no custom `models.json` provider override/proxy redirects `openai`. If any check is uncertain, stop. For raw Pi/Limen commands these checks are a human preflight, **not** a fail-closed enforcement mechanism: Pi's credential precedence puts runtime `--api-key` above stored OAuth. The bounded wrapper below fails closed for its own invocation only. `LIMEN_PREFLIGHT=auth` adds a Pi auth readiness check when set, but Limen does not inspect the credential type or billing. A `ready` result and a previous trial do not verify plan entitlement or prevent paid extra usage. Keep credentials in Pi's private user store outside this repository; never set an API key for this workflow.

Delegate only when independent work improves the result. Default to **one** worker/reviewer at a time; allow up to **three** independent, non-overlapping jobs when resource readings and task value justify it, as in the issue #1/#4/#8 trial. Start conservatively and inspect artifacts before integration. For short bounded spawns, prefer `scripts/limen-oauth.sh worker 'label' 'task'` or `scripts/limen-oauth.sh reviewer BRANCH 'label' 'review task'`. It pins engine/provider/model/thinking, 10 minutes and 50 tool calls after checking OAuth type and rejecting `OPENAI_API_KEY`, `OPENAI_BASE_URL` and OpenAI model-catalog overrides. It cannot verify billing or stop an agent from using other commands after launch. For larger issue jobs, use explicit flags and preflight with at most 80 tool calls and 20 minutes per job. These are per-job controls, not a seat-wide cap. Require explicit route flags above. Do not use hosted `--tab` for a bounded trial: it has no outer timeout or tool-call cap. Do not start `limen continue` as an unbounded substitute: its help has no `--timeout`; inspect its limits before any continuation. Stop on route/auth failure, observed billing or entitlement warning, rate limiting, repeated failure, or unexpected costs. Do not switch to paid usage, exceed the selected task limits, or retry on a different provider. Time and tool limits and the one-to-three-job operating rule are **not** a token limit, hard concurrency guard, or spending cap; Pi's catalog cost display is an estimate, not a billing guarantee.

## Evidence and reconsideration

Checked on 2026-10-29 on Linux x86_64: Pi 1.4.0 `pi auth check --provider openai --model gpt-6-sol --json --no-refresh` reported `status: ready`, `provider: openai`, `authType: oauth` (no credential output); the `openai-codex` check did not report readiness. Installed Limen revision `3419a4ca62eb3de413e30fc3c417952ff3c20847` exposes explicit spawn route/thinking/timeout flags, optional `LIMEN_PREFLIGHT=auth`, and `LIMEN_MAX_TOOL_CALLS` in its local runtime. Pi's installed `docs/models.md` describes credential precedence and `docs/providers.md` describes the private store. The wrapper's mocked-auth checks run via `scripts/test-limen-oauth.sh` without a model call; no wrapper invocation on macOS has been tested. Neither the metadata check nor this wrapper verifies current plan billing, paid-extra controls, or account entitlement. Recheck versions and the plan before relying on this policy on another host. Reconsider model choice only after representative tasks show a reliable lower-resource OAuth model on the same approved plan; do not infer price from catalog estimates alone.
