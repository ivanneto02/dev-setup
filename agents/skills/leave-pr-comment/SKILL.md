# Leave a PR comment

1. Read the PR description, relevant diff, and existing discussion. Check the current PR state and source before making factual claims. If the PR is inaccessible, ask for the missing context; do not guess.
2. Identify one specific contribution not already made in the PR or comments: a verified concern, an actionable question, or a useful observation with evidence. Do not repeat the PR summary, offer generic praise, or invent test results. If there is nothing useful to add, say so and do not post.
3. Draft a short comment that leads with the point and includes only the context needed to act on it. Cite a file or behavior when relevant. Separate observed facts from uncertainty; phrase unverified concerns as questions, not findings.
4. End the comment with a separate final line: `AI-assisted: Pi` when written with Pi. In another harness, use `AI-assisted: <harness name>` instead; do not claim Pi authored text it did not create.
5. Post only when the user has authorized publication of this comment. If asked only to draft, return the draft without posting. Check the posted text if possible and report the link; if posting fails, report the failure without claiming success.
